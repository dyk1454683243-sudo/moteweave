Source only · local first · v0.6.0

Pixel character packs, on your machine.

MoteWeave is a local-first workflow for people who prepare top-down pixel characters, edit sprite canvases, and write files other game tools can read. Studio is the default app. VNext is an opt-in workspace for v1 projects.

This public repository is a source-only preview. It does not host uploads, accounts, or billing. This website does not accept files and does not call models.

The website does not provide user file upload or cloud processing. Full processing runs in the local app after you clone the source.

01 — Workspace

VNext workspace and text assistants

v0.6.0 adds an opt-in VNext workspace for v1 projects and documents. Studio stays the default entry. The local server still opens Character Studio first.

Three native text assistants — Codex, Grok, and Antigravity — can discuss the open project or apply one selected creative action, with undo. The v0.6.0 model menu labels are Grok 4.7, GPT 6.1 for Codex, Gemini 3.8 Flash for Antigravity, and Astra. Native installs and account login are prerequisites. They are not bundled with this repository.

02 — Canvas

Native pixel tools

The editor canvas can draw without a provider. v0.6.0 adds brushes, fill, eraser, color controls, onion skin, a project palette, timeline structure, and document export.

Linked cels

A change to a shared cel updates the frames that use it. A provider-free pixel-tools CLI can draw on a local candidate. It does not call a model, and a person confirms whether to save.

Selection, text, display, PNG

Pixel selection, editable canvas text, and canvas display settings are in the workspace. The file control downloads the selected saved canvas’s currently displayed frame as a PNG, at its original pixel dimensions. That file is not a multi-frame sheet and not a whole-project export.

History storage

The open project keeps a small current state. The full edit history stays on disk, so longer pixel-editing sessions can still save. Existing undo and redo behavior is unchanged. The v1 history protocol adds no full-history download endpoint and no new history UI.

Astra animation

With an explicit skill, Astra draws distinct frames and timings on the selected canvas and applies them as one undoable change. The in-app Astra adapter is not established as live-verified.

03 — Studio

Studio stays the default

The visible rail is Character, Extract, Sequence, Map, Project, Self-check, and Settings. Extract opens Frame Extraction. Map opens Map Studio. The Scene rail item is hidden, and #scene opens Map Studio.

v0.6.0 retired the Studio character compatibility generation flow. Reviewed generation and advanced local processing stay. Character review and advanced options are simpler, Tiles build outputs are clarified, and each module has one primary action.

  • Character Local sprite-sheet import and the character pack workflow. The capture uses a fixed-region motion source.
  • Extract Frame Extraction reads local media. The page title in the app is Frame Extraction.
  • Sequence Sequence Studio imports local frames. After loading, frames are naturally sorted by filename.
  • Map Map Studio turns terrain material into an editable map. Tile structure is generated by local rules. AI is not called automatically.
  • Project Project Pack combines existing character and scene artifact directories into project_pack.zip.
  • Self-check and Settings Self-check is the QA module. Settings holds local options, including provider routing when you choose to use one.

04 — Exports

Files the local app actually writes

Exporters sit on the normalized character sheet. The scene tile path writes its own pack. None of these run in the browser on this website.

  • Godot NPC JSON godot_npc_pack.zip includes AI资源库/一图全动作/<character_id>/npc.json, sprite.png, and thumb.png. The NPC document uses schemaVersion 1.
  • RPG Maker rpgmaker_pack.zip uses a 144×192 sheet, 3 columns by 4 rows, 48×48 frames, and NPC.json.
  • OCAD compatibility ocad_pack.zip includes 252×252 fixed-region sheets and npc.json.
  • LDtk The scene tile path writes a single-level project.ldtk plus scene_pack.zip. Multi-level LDtk worlds are not implemented.
  • Character pack character_pack.zip and editor_metadata.json carry the normalized sheet, frame tags, slices, and attachments.
  • Project pack project_pack.zip combines an existing character artifact directory and a scene artifact directory.

05 — Boundaries

What v0.6.0 does not do

  • Godot .tres export is not implemented.
  • Full WFC, multi-level LDtk worlds, expanded auto-layer rules, region-scoped generation, and saved external-editor round trips are not implemented.
  • Full parallax asset generation is not implemented.
  • Broad scene and tile quality claims are not supported. The live scene evidence is a one-case release smoke.
  • AI generation is an optional path. Local sheet processing does not require it.
  • Hosted production persistence, auth, billing, and public deployment hardening are not part of this preview.
  • The fixed-region calibration path has passed one single-call 1K acceptance. That result is one reviewed run, not a production-readiness claim.

06 — Start

Getting started

Node.js 22 or 24 is required. Node.js 24 LTS is recommended. Install from the lockfile, then open the local URL printed by npm start. The server listens on 127.0.0.1. The default port is 4173. The root path opens Character Studio.

Commands

$ git clone https://github.com/dyk1454683243-sudo/moteweave.git
$ cd moteweave
$ npm ci
$ npm start
