# Sprite Document Protocol v1

**Status:** Active for the approved `P2-02_STORE_COMPAT/r1` data foundation<br>
**Owner:** Editor Workspace<br>
**Introduced:** 2026-09-18<br>
**Plan:** `docs/plans/2026-09-07-gametool-vnext-master-plan.md` §5.4.3

## Purpose

`editor_project_v1` is the sole commit index for a VNext project. Sprite
documents are immutable manifests plus immutable RGBA8 blocks. This protocol
does not authorize workbench save, painting, publish, UI, or generation.
Approved r1 canvas commands are PNG import and canvas-position save only.
The protocol version is unchanged. Two later compatibility exceptions are
optional `canvas.display_name` and raw JPEG import.

Old `editor_project_v0` files stay readable. Copy-upgrade creates a new project
id. In-place migration and a parallel v0 sidecar are not part of this protocol.

## Project Index

`workspace/projects/<project-id>/project.json` is the only authoritative
commit point. Applicable v0 fields are retained.

```json
{
  "version": "editor_project_v1",
  "id": "p0123456789abcdef",
  "name": "Untitled Project",
  "revision": 1,
  "created_at": "2026-09-18T00:00:00.000Z",
  "updated_at": "2026-09-18T00:00:00.000Z",
  "active_scene_id": "scene_main",
  "assets": {},
  "scenes": {},
  "scene_flow": { "nodes": {}, "links": [] },
  "settings": {
    "pixel_art": true,
    "default_snap": 16,
    "default_viewport": { "w": 1280, "h": 720 }
  },
  "upgraded_from": null,
  "pages": [{ "id": "page_1", "name": "Page 1", "canvas_order": [] }],
  "canvases": {},
  "conversation_id": null,
  "sprite_documents": {},
  "operation_receipts": {}
}
```

Rules:

- `version` is `editor_project_v1`. Clients cannot write version, source
  provenance, revision, accepted revision, or receipts.
- `revision` is a positive integer generated by the server.
- Optional `settings.palette = { colors: [[r,g,b,a], ...] }` is one ordered
  project palette: 0–256 four-byte integer tuples, no extra palette keys.
  Absence uses the UI's default 24 colors without writing; `[]` is empty.
  It is independent of manifest palettes, pixels, working/accepted revisions
  and drawing history. The two working colors are tab-local, not persisted.
- `POST /api/editor/projects/:pid/palette` accepts only JSON
  `{ operation_id, expected_revision, colors }`, maximum 64 KiB. It requires
  UUID operation ID, positive expected project revision and v1 project;
  responds `200 { project, receipt }`. It reuses local Origin protection,
  the project mutation lock, identical-operation replay and atomic publication.
  Only project revision increments. Errors: 400 `invalid_request`,
  403 `forbidden_origin`, 404 `not_found`, 409 `stale_revision`/
  `operation_conflict`, 413 `resource_limit`, 422 `unsupported_input`,
  500 `storage_commit_failed`. No legacy write or migration change.
  A submitted unknown result retains the original request and write lock;
  retry cannot allocate a new operation. Confirmed saves with failed reloads
  retry GET only. Dialog dismissal is not write cancellation.
- `upgraded_from` is `null` or `{ "project_id", "revision" }`.
- First-usable projects have exactly one page.
- `canvases` map canvas id to `{ id, page_id, document_id, x, y }`.
  `display_name` is optional. When absent, clients show the document
  manifest name. A present name is 1–128 trimmed characters without
  controls. Other canvas fields stay as they were.
- `conversation_id` is an association only.
- `sprite_documents[id]` stores `{ id, working_revision, accepted_revision,
  revisions: { n: { manifest_sha256, parent_revision, created_at } } }`.
- New documents start at `working_revision = 1` and `accepted_revision = null`.
  Old asset production status never auto-promotes accepted.
- `operation_receipts` bind `operation_id`, payload hash, and the committed
  result so a lost HTTP acknowledgement can replay the same operation.

## Document Manifest

Stored at
`workspace/projects/<pid>/sprite-documents/<did>/revisions/<n>.json`.
The manifest includes its own revision and parent. There is no second mutable
current index.

```json
{
  "version": "sprite_document_v1",
  "document_id": "d0123456789abcdef",
  "project_id": "p0123456789abcdef",
  "name": "Untitled Document",
  "revision": 1,
  "parent_revision": null,
  "canvas": { "w": 96, "h": 96 },
  "color": { "format": "rgba8", "alpha": "straight", "space": "srgb" },
  "frame_order": ["frame_1"],
  "layer_order": ["layer_1"],
  "frames": { "frame_1": { "id": "frame_1", "duration_ms": 125 } },
  "layers": {
    "layer_1": {
      "id": "layer_1",
      "name": "Layer 1",
      "kind": "raster",
      "visible": true,
      "locked": false
    }
  },
  "cels": {
    "cel_frame_1_layer_1": {
      "id": "cel_frame_1_layer_1",
      "frame_id": "frame_1",
      "layer_id": "layer_1",
      "block": { "sha256": "<64 lowercase hex>", "w": 96, "h": 96 }
    }
  },
  "tags": [],
  "palette": [],
  "anchors": [],
  "source_ref": {
    "asset_id": "asset_hero",
    "revision_id": "rev_001",
    "artifact": "sheet",
    "expected_sha256": "<64 lowercase hex>"
  }
}
```

Duration keeps per-frame source values. Missing durations are derived from a
verified fps. Identical pixels may share an immutable block. Cels keep
independent ids; equal blocks alone are not Link copies. `derived_from` is optional and
server-generated only: `{ document_id, revision, manifest_sha256 }`. It does
not replace `source_ref`. Manifests without it remain valid.

Approved `LINK_COPIES/r1` adds optional top-level
`links: { copy_layers: [layer_id, ...], groups: { group_id: [cel_id, ...] } }`.
The object has exactly these two keys. Copy layers exist and are unique;
each nonempty group has a stable server-generated ID and unique existing
members from one layer. Each cel belongs to at most one group and all members
have identical full block references (or all null). Groups are document-local.
Missing links means all preferences off and no groups, without migration or
automatic writes. Turning a preference off never breaks existing groups.
This optional top-level extension intentionally fails closed in older writers
that reject unknown top-level fields, rather than allowing silent single-cel
updates that discard or corrupt relationships. Manifest/resource limits remain.

Approved 2026-10-06 `COMPACT_MODEL_EDITABLE_TEXT/r1` adds optional top-level
`text_objects`. Absence means no text objects and remains valid for every older
document. Presence is exactly `{ version: 1, items: [...] }` with at most 32
items. Each item is exactly `{ id, frame_id, layer_id, text, x, y, size, font,
bold, italic, antialias, mode, stroke_width, color }`. `text` is 1–160
characters and at most 4 lines. `x`/`y` are signed safe integers in image pixels;
the text box may extend beyond any canvas edge (approved 2026-10-11
`TEXT_CANVAS_CLIPPING/r1`). `size`
is 6–96. `font` is `{ kind: "generic", name: "sans-serif"|"serif"|"monospace" }`
or `{ kind: "local", name: "<postscript name>" }`. No font bytes, paths, or
uploads are stored. `mode` is `fill`, `stroke`, or `both`. `stroke_width` is
1–8. `color` is `#` plus 8 lowercase hex digits. Items belong to an existing
unlocked frame and raster layer. An empty item list omits the field. Pixel
writes, structure edits, and derive-working clone the manifest and keep this
field; they must not strip it. `copy-frame` duplicates that frame's text objects as new independent ids and does not create a text link; a copy that would exceed 32 items is rejected. Delete and update check the object's original layer lock, and an update also checks the destination layer. Frame and layer ids must be own order members, not inherited properties. A writer that does not understand version 1
rejects the document instead of saving a copy that drops the objects. Already
rasterized pixels are not reconstructed as text objects. Image export may
composite these objects into pixels; that composite is not written back over
the source objects. Preview, frame PNG and each atlas cell clip only the rendered
pixels to that canvas; they never truncate the stored text, auto-wrap or shrink
it. Fully clipped objects remain valid and can be moved back into view. Older
writers with in-canvas coordinate validation may reject these positions, but
must never silently clamp or discard them. Selection, caret, and IME composition stay out of the
manifest.

## Pixel Blocks

Blocks live at
`workspace/projects/<pid>/sprite-documents/<did>/blocks/<sha256>.rgba`.

- RGBA8, straight alpha, sRGB.
- Four channels, including RGB bytes when alpha is 0.
- Length must equal `w * h * 4`.
- File name, header, and content hash must match.
- Blocks and manifests are immutable. Staging leftovers are not loaded and
  are not auto-deleted.

Commit order: write and fsync immutable blocks and the manifest, then
atomically switch `project.json` under the project lock. A failed commit must
not change the authoritative version. A committed index with a lost
acknowledgement is recovered by the same `operation_id`.

## Routes

New routes plus the existing GET project adapter:

- `POST /api/editor/projects/v1` `{ operation_id, name? }`
- `POST /api/editor/projects/:pid/upgrade-copy` `{ operation_id, expected_revision, name? }`
- `POST /api/editor/projects/:pid/sprite-documents` managed PNG/sheet source only
- `GET /api/editor/projects/:pid/sprite-documents`
- `GET /api/editor/projects/:pid/sprite-documents/:did?revision=n`
- `GET /api/editor/projects/:pid/sprite-documents/:did/blocks/:sha256`

Create and upgrade derive the target id from the operation. The same
operation and payload replay as 200. A different payload on the same
operation is `operation_conflict`.

Approved canvas-command routes:

- `POST /api/editor/projects/:pid/sprite-documents/from-job`
  JSON `{ operation_id, expected_revision, source:{ job_id, artifact,
  expected_sha256 }, name? }`. Unknown fields are rejected. `artifact` is
  the semantic key `sheet`. Only a completed, quality-pass ordinary
  character-pack process Job is accepted. Generation, specialized repair,
  and historical reprocess Jobs are rejected. The server reads the Job
  through the injected generated store and the fixed whitelist
  `normalized_sheet.png`, `animations.json`, `metadata.json`,
  `editor_metadata.json`, `debug_report.json`. It copies those files into a
  new immutable managed `character_pack` revision, then commits the asset,
  multi-frame RGBA document, canvas at `x=y=0`, and receipt in one
  `project.json` write. `source_ref` stays
  `{ asset_id, revision_id, artifact, expected_sha256 }`; the Job id is
  `revision.source_job_id`. Same-op replay returns the original receipt
  without rereading the Job. First success is 201; replay is 200.
  Response `{ project, document, receipt }`. Working revision is 1;
  accepted stays null.
- `POST /api/editor/projects/:pid/sprite-documents/import-png`
  `Content-Type: image/png`, raw bytes. Query only
  `operation_id`, `expected_revision`, `expected_sha256`, optional `name`.
  Encoded query ≤ 2 KiB. Body ≤ 32 MiB. Static 8-bit non-interlaced sRGB
  PNG only; reject APNG, ICC, and non-sRGB color declarations. Store the
  original bytes as a `static_image` `image` artifact with
  `provenance.source_type='upload'`, then commit the asset, one-frame
  document, and a new canvas at `x=y=0` in one `project.json` write.
  First success is 201; same-op replay is 200. Response
  `{ project, document, receipt }`.
- `POST /api/editor/projects/:pid/sprite-documents/import-jpeg`
  `Content-Type: image/jpeg`, raw bytes. Query fields match import-png and
  stay within 2 KiB. Body stays within 32 MiB. This is not a rebuild and
  does not scale. The server checks the JPEG signature and Sharp metadata
  before decode, using the existing Sharp input-pixel limit, and rejects an
  oriented edge above 1024 or a decoded RGBA above 4 MiB before commit.
  EXIF rotation and mirror are applied. An embedded profile that cannot be
  converted is rejected before commit. The working pixels are 8-bit sRGB
  RGBA with alpha 255. Original bytes are stored unchanged as `image.jpg`.
  `source_ref` still points at that original JPEG and its hash. The RGBA
  block has its own hash. The document is one frame and one layer,
  `working_revision` is 1, `accepted_revision` is null, and `derived_from`
  is absent. `import-png` and its rejection rules are unchanged. First
  success is 201; same-op replay is 200. Response `{ project, document, receipt }`.
- Native image bridge (`NATIVE_IMAGE_EMBED/r2`), all under the same
  loopback/same-origin guard and existing v1 project:
  `GET /api/editor/projects/:pid/image-generation` reports native CLI availability,
  not authenticated success; `providers` lists each provider's model and billing boundary.
  `POST` takes only `{ operation_id: UUID, description: nonempty string <= 4000 characters,
  provider?: 'antigravity' | 'codex' | 'grok', reference?: {canvas_id, document_id,
  expected_revision, working_revision} }`; reference requires an explicit provider.
  Omitted provider preserves the older
  Antigravity request. New UI requests freeze the existing right-side selector choice.
  It starts one isolated, signed-in native session after configuration/version checks;
  no API keys, provider fallback or wrapper retry.
  Reference generation is advertised per provider (`reference_upload`); currently Codex only.
  An explicit reference intent requires selecting an imported canvas; confirmation names it.
  Only that project's matching canvas/document and saved revisions are read (one full-size
  cel, one frame/layer, edge <=1024). Server-verified RGBA is encoded as PNG without resizing;
  no client paths, URLs or image bytes are accepted. A changed reference fails before any
  provider invocation, unsupported providers reject instead of silently discarding it.
  New Codex sessions receive one inline image with empty environments; native imagegen
  may reference that image and process its own generated output, never local files.
  This permission does not make ordinary discussion turns image-aware.
  Antigravity uses `gemini-3.8-flash-low` + `generate_image`, extra credits disabled.
  Codex uses `gpt-6.1-sol` + native `image_gen.imagegen` (`gpt-image-2`); media notifications
  omit base64 and only the exact native thread/call PNG is read. The supervised session
  ends after the first successful image receipt. Grok uses `grok-4.7` + `image_gen`,
  recorded as `native-imagine` rather than claiming a verified underlying image-model ID.
  Its `dontAsk` permissions allow only `image_gen`; the exact session image is read.
  Codex/Grok follow native account billing, including existing extra credits where
  applicable; no per-call subscription-only switch is claimed. Confirmation states this.
  Codex image generation is enabled following explicit user approval of internal reuse of
  this turn's generated output. The old strict no-reference gate is superseded; a fresh
  thread and empty environments still prevent arbitrary local reference reads.
  All request one square 1024 image, but native sizing is not guaranteed. Native internal
  request count is not controlled by this bridge. HTTP 202 returns the operation
  ID as job ID. Identical requests replay the receipt; changed text with the same
  ID, provider or reference tuple returns 409. One generation runs at a time.
  Project-owned `runtime/images` sidecars persist receipts and validated source bytes
  (each original <=8 MiB plus its <=1024 fitted PNG when needed). The 16-entry
  memory cache may evict terminal entries without deleting durable deduplication
  records. Restarted in-flight jobs become `unknown`; they are never resubmitted.
  `GET /.../image-generation/recent` lists the latest 32 project jobs and whether
  their source job IDs already have imported assets. Reading does not call a provider.
  `GET /.../image-generation/:job` queries that project's job and
  `GET /.../:job/source` returns the canvas-ready image. Native PNG/JPEG results
  are bounded to 8 MiB, 4096 per edge and 4096² decoded pixels, fully decoded
  before fitting. Static sRGB PNG rules, JPEG profile validation and EXIF orientation
  remain enforced. Results within 1024 retain their exact bytes; larger results
  use nearest-neighbor proportional fit inside 1024×1024, no crop/upscale, encoded
  as PNG. Job `sha256`, dimensions and MIME describe this canvas-ready image.
  Fitted jobs additionally expose `fitted: true` and original hash/MIME/oriented
  dimensions (not pixels or local paths).
  No native filesystem path, account details or raw CLI log is public.
  `POST /.../:job/import` has an empty body and the existing import query fields
  (`operation_id`, `expected_revision`, `expected_sha256`, optional `name`).
  The server obtains bytes and provenance from the retained job, adds the job
  identity to the frozen receipt payload, and uses the existing atomic importer.
  For fitted results it persists immutable `native_original` and
  `generation_metadata` artifacts in the same asset revision, before publishing
  the project/receipt. Metadata binds original and fitted hashes/dimensions to
  the job and nearest/fit transformation. Original native files are never overwritten.
  Same-op import retries reuse those exact bytes and identity. Undo/Redo detaches/
  restores the new canvas only; neither original nor fitted assets are deleted.
  Import also checks source job identity under the existing project mutation lock.
  A different operation ID for an already imported job returns HTTP 200
  `{ project, already_imported: true }`, without moving, restoring or duplicating
  its canvas, or manufacturing a receipt for the new operation ID.
  The asset is `source_type='provider'`, with provider/model from the frozen server adapter
  and `source_job_id` set. Clients cannot submit source
  provenance or pixels through this bridge. Ordinary PNG/JPEG upload remains
  unchanged. Import is 201/replay 200 and does not save other layout drafts or
  mark an accepted revision. A lost generation reply resumes GET using the
  frozen operation ID; it never resubmits generation automatically.
- `POST /api/editor/projects/:pid/sprite-documents/derive-working`
  JSON `{ operation_id, expected_revision, source_canvas_id, source_document_id, source_revision, name? }`.
  Same-project source canvas must point at the source document, and
  `source_revision` must be that document's current working revision.
  Approved structure extension (2026-10-03): the complete supported RGBA8
  raster structure is copied, without scaling or flattening. Each explicit
  frame/layer intersection has a full-canvas block or null (blank) cel;
  unknown rendering fields are rejected rather than discarded. Layer/frame
  identities, order, visibility/locks, durations and existing metadata survive.
  Immutable equal blocks do not make linked cels. Explicit optional `links`
  topology and copy preferences survive a derive, but groups never propagate
  across document boundaries. The server creates a new
  document and canvas, copies pixels
  and the existing `source_ref` unchanged, and sets server-only
  `derived_from: { document_id, revision, manifest_sha256 }`. Old manifests
  without `derived_from` stay valid. The new canvas is placed on the same
  page to the right of the source; collisions search only rightward across
  at most 64 boards. Old coordinates are not changed. First success is 201
  `{ project, document, canvas, receipt }`; same-op replay is 200 and does
  not choose a new position.
- `POST /api/editor/projects/:pid/sprite-documents/:did/working-pixels`
  `Content-Type: application/octet-stream` raw RGBA8. Query only
  `operation_id`, `expected_revision`, `expected_working_revision`, `x`,
  `y`, `w`, `h`, `expected_sha256`, encoded at most 2 KiB. Body must be
  exactly `w*h*4` and at most 4 MiB. This binary limit does not change the
  64 KiB JSON limit. Only a document with `derived_from` can be written;
  the target layer must be unlocked. Legacy untargeted requests require one
  frame/layer/cel. The write applies the rectangle to that cel.
  Inside the project lock, revision allocation starts at
  `committedMax+1` and checks at most 64 candidates, through
  `committedMax+64`. An empty slot is a new write. An uncommitted slot with
  identical manifest bytes is reused and its directory durability is
  confirmed again without rewriting the file. A different uncommitted slot
  is kept and skipped. Exhaustion returns 413 `resource_limit` and does not
  commit a new index. Revision numbers may contain gaps. Committed revisions
  are never overwritten, and leftover files are not deleted.
  Approved scoped extension (2026-10-03): optional `frame_id`, `layer_id`,
  `cel_id` must be supplied together and name one unlocked cel in this derived
  document. Without them the legacy single-cel-only restriction remains.
  A scoped command also supplies `grant_id` and `command_sha256` together.
  Its rectangle and exact bytes/hash must match the frozen grant command.
  For unlinked cels only this cel rectangle is patched; outside pixels and
  other cels remain byte-identical. For explicitly linked cels, a current group
  grant and matching command hash are mandatory even without a selection.
  All members receive the same new immutable block in one atomic revision;
  nonmembers and pixels outside the rectangle remain unchanged. Missing/old
  single-cel grants and untargeted legacy writes cannot modify a linked group,
  including a remaining one-member group. Receipt replay precedes stale-grant rejection.
  `parent_revision` is the previous working revision. The working revision
  switches atomically and the project revision increments by 1. Accepted
  revision, source, canvas size, and canvas position stay unchanged.
  Response 200 `{ project, document, receipt }`.
- `POST /api/editor/projects/:pid/sprite-documents/:did/scope-grants`
  Local JSON `{operation_id, expected_revision, expected_working_revision,
  frame_id, layer_id, cel_id, rect:{x,y,w,h}, allowed_operations, command?, link_scope?}`.
  Operations are the closed drawing set plus `working_pixels`; command, when
  present, is `{rect:{x,y,w,h}, sha256}` for one exact binary pixel patch.
  Issuance validates target, unlocked layer, bounds and both current revisions
  under the project lock. `{grant}` is returned only after persistence in the
  existing trusted `runtime/grants` record boundary. No document/project
  revision, accepted asset or pixel is changed. Same operation/content replays;
  other content conflicts. The server binds project/document/target and
  canonical command hash, plus the source cel block read dependency. Stale,
  foreign, missing or corrupt records are rejected, not renewed automatically.
  Metadata-only assistant requests may carry a read grant: `grant_id` joins
  their operation fingerprint and the server constrains returned proposals.
  After explicit Apply derives a copy, a separate write grant names that exact
  returned document/revision/cel and unchanged selected rectangle; the source
  grant is never reused for the copy. Unknown grant writes replay the same ID.
  Approved `LINK_COPIES/r1` (2026-10-04): linked targets require explicit
  `link_scope:{group_id,cel_ids}` matching the complete current group. The
  server sorts member IDs, freezes the group and all member block read
  dependencies, and includes the scope in the exact pixel command hash.
  Group changes invalidate the grant. Unlinked targets retain prior behavior;
  a legacy request is never silently promoted to group authority.
- `POST /api/editor/projects/:pid/sprite-documents/:did/working-structure`
  Local JSON, no query, at most 64 KiB:
  `{operation_id, expected_revision, expected_working_revision, command}`.
  Only supported derived documents; no client manifest snapshots. Closed commands:
  `add-layer {name}`, `rename-layer {layer_id,name}`,
  `set-visible/set-locked {layer_id,value}`, `add-frame {}`,
  `copy-frame {frame_id}`, `set-duration {frame_id,duration_ms}` (each includes
  `type`). Names are trimmed 1–120 characters; duration is integer 1–60000 ms.
  A new top layer is visible/unlocked and all its cels blank. Frames append:
  blank is 125 ms with a new null cel per layer; copy preserves source duration
  and independent new cel identities. Server generates IDs.
  Approved 2026-10-04 timeline extension: `delete-frame {frame_id}`,
  `delete-layer {layer_id}`, `move-frame {frame_id,index}` and
  `move-layer {layer_id,index}` (all include `type`). `index` is the integer
  zero-based final position, within the existing order. Moves retain stable
  IDs, all cels, duration and attributes. Deletion removes only the target and
  its cels from the new manifest, never historical files or blocks. Keep at
  least one frame and layer. A locked layer cannot be moved/deleted; deleting
  a frame requires all layers unlocked. These four commands reject nonempty
  tags/anchors because their reference semantics are not supported here.
  Approved `LINK_COPIES/r1`: `set-layer-link-copies {layer_id,value}` stores a
  boolean preference for future copy-frame only. Linked-copy layers join the
  source cel's explicit group, or create a new server-identified group with
  source and copy. Off creates an independent new cel without unlinking old
  groups; add-frame remains empty and unlinked. Locked layers cannot toggle
  the preference or gain group members: a copy touching any enabled locked
  layer rejects as a whole. Deletion removes members and empty groups; a
  one-member group retains identity; layer deletion also removes its preference.
  Moves preserve relationships. No manual link/unlink or FPS batch rewrite.
  Caps remain 32 layers/256 frames; source pixels are immutable.
  Existing project lock, dual base revisions, immutable revision publication,
  same-op receipt replay/conflict and resource limits apply. Response 200
  `{project,document,receipt}`. Structure and pixels publish one new working
  revision; accepted/source/canvas size/position remain unchanged.
- `POST /api/editor/projects/:pid/sprite-documents/:did/restore-working`
  JSON `{ operation_id, expected_revision, expected_working_revision, target_revision, mode? }`.
  Restores one existing revision of the same derived document into a new
  revision using the same allocation rule as working-pixels. It does not
  rewind revision numbers, delete history, or change accepted. Response 200
  `{ project, document, receipt }`. Reopen uses the existing revision and
  block reads. In-memory undo is not persisted.
  Without `mode`, legacy restoration stays single-frame/single-layer pixels
  only. Explicit `mode:"structure"` restores `frame_order`, `layer_order`,
  `frames`, `layers`, `cels`, optional `links` and their verified existing blocks from the same
  derived document's target revision. It permits undo of a lock operation but
  never changes dimensions, color contract, provenance, accepted or position.
  No arbitrary client structure is accepted; unsupported semantics reject.
  A historical revision without links removes that optional field on restore.
  Legacy pixel-only restore rejects if either snapshot contains links.
- `POST /api/editor/projects/:pid/canvas-layout`
  JSON `{ operation_id, expected_revision, positions:[{ canvas_id, x, y }] }`.
  Updates only listed existing canvas `x/y` values. Project revision
  increments; document revision, working/accepted, manifests, and blocks
  stay unchanged. Response 200 `{ project, receipt }`.
- `POST /api/editor/projects/:pid/canvases/:cid/rename`
  JSON `{ operation_id, expected_revision, display_name }`. Unknown fields
  are rejected. The route canvas id is bound into the receipt payload and
  hash; the same operation sent to another canvas is a conflict, not a
  replay. A stored canvas may omit `display_name`; that is not permission for
  the rename request to omit it. An explicit null is invalid.
  This changes only that canvas `display_name`, `updated_at`,
   and project revision by 1. Manifest, working and accepted revisions,
   source, pixels, and coordinates stay unchanged. It does not write through
   canvas-layout. Response 200 `{ project, receipt }`. Same-op replay returns
   the original receipt. A lost acknowledgement can be retried with the same
   operation and payload. A stale revision or payload conflict is not retried
   with a newer revision.
- `POST /api/editor/projects/:pid/canvases/:cid/reset-name`
  JSON `{ operation_id, expected_revision }`. Unknown fields, `display_name`,
  and null are rejected. This is the only way to remove a stored
  `display_name`. It deletes that field when present, updates `updated_at`,
  and increments project revision by 1. It does not write a replacement name,
  and the rename route still rejects an omitted or null name. Manifest,
  working and accepted revisions, source, pixels, and coordinates stay
  unchanged. Response 200 `{ project, receipt }`. Same-op replay returns the
  original receipt. A lost acknowledgement retries the same operation and
  payload. A 409 is not retried with a newer revision.
- `POST /api/editor/projects/:pid/canvases/:cid/detach`
  JSON `{ operation_id, expected_revision }`. Removes that canvas from
  `canvases` and from its page `canvas_order` only. The server receipt records
  the removed canvas identity, position, optional name, page, and order index.
  The client does not send that snapshot. Documents, blocks, manifests,
  source, accepted revisions, and older receipts stay in place and are not
  deleted. The retained document still counts toward the 64 document limit.
  Response 200 `{ project, receipt }`.
- `POST /api/editor/projects/:pid/canvases/:cid/restore`
  JSON `{ operation_id, expected_revision, detach_operation_id }`. Restores
  the canvas recorded by that detach receipt: the same canvas id, document,
  position, name presence, and page order. It does not upload, import, or
  accept a client project snapshot. A different payload for the same
  operation is 409. Response 200 `{ project, receipt }`.

Approved read-only list route:

- `GET /api/editor/projects`
  No query or request body. Response
  `{ projects:[{ id, name, version, revision, updated_at }], omitted_count }`.
  Reads only the configured `workspaceRoot/projects` first-level legal-id
  directories' `project.json`. Index `id` must match the directory. Sort
  `updated_at` descending, then `id` ascending. Names are not truncated.
  Bad single items increment `omitted_count`. An unsafe or unreadable root
  is a whole failure, not an empty list. Zero writes; does not upgrade or
  replace GET `/:pid`.

## Errors And Limits

`400 invalid_request`, `403 forbidden_origin`, `404 not_found`,
`409 stale_revision|operation_conflict|unsupported_project_writer`,
`413 resource_limit`, `422 unsupported_input|artifact_integrity_failed`,
`500 storage_commit_failed`.

Limits: canvas edge 1024; 256 frames; 32 layers; 4096 non-empty cels; 128 MiB
expanded RGBA (dedup does not bypass); managed or uploaded PNG or JPEG 32 MiB;
decoded import RGBA 4 MiB; sheet
decode 4096² pixels; JSON request 64 KiB; import-png and import-jpeg query 2 KiB; manifest
  and project JSON 2 MiB each; 64 canvases or documents per project;
  working-pixel and restore allocation checks at most 64 candidates after
  the committed maximum;
copy-upgrade 512 MiB and 4096 managed files; pixel cache 256 MiB lazy.
List read: 512 first-level entries; 256 candidates including omitted
items; single index 2 MiB; cumulative read 32 MiB; serialized response
256 KiB. These list budgets do not change stored project JSON limits.

## Old Writers

Stored `editor_project_v1` rejects old POST overwrite, PUT, autosave,
import-job, dedicated accept, and the underlying store. Forged request
`version` cannot write v1. Old delete/unlink reject v1 and must not inspect
only scene layers. Old `export-pack` is unsupported for v1. v0 behavior is
unchanged. Source v0 files are not modified in place.
