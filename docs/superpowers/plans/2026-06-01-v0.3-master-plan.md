# v0.3 Master Plan

**Date:** 2026-06-01
**Status:** Completed on 2026-06-04

## Goal

Ship v0.3 as a reliable character-pack pipeline release before expanding into broader scene, layer, or repair workflows.

## Execution Order

1. v0.3 startup cleanup and decoupling.
2. Generation quality closure.
3. Output experience polish.
4. Version and release closure.

## Phase 0: Startup Cleanup And Decoupling

This phase reduces maintenance risk before more quality and export work lands.

Required:

- Split `src/character-pack/processSheet.js` into explicit pipeline stage helpers while keeping `processSheetBuffer()` as the public orchestration entry point.
- Split `src/character-pack/providers/geminiProvider.js` so provider config, prompt/image request assembly, Gemini transport, and OpenRouter transport are separate modules.
- Keep all public behavior and artifact contracts unchanged unless a protocol document is updated in the same commit.
- Preserve existing tests and add focused coverage around any newly exported helpers.

Documentation cleanup:

- Keep only current v0.3 plans in `docs/superpowers/plans/`; move completed historical execution plans into `docs/superpowers/plans/archive/`.
- Use specific benchmark protocol names so processed, local compatibility, and live OpenRouter reports are not confused.
- Update roadmap statuses when data-layer work has shipped but follow-up exporter or UI work remains.

Deferred from Phase 0:

- `src/character-pack/sourceLayouts.js` data-table extraction.

Completed Phase 0 follow-up:

- `src/ui/characterPackTab.js` controls were split into `src/ui/characterPack/controls.js`.
- The unused compact legacy template file was removed from active docs and `templates/`.

## Phase 1: Generation Quality Closure

Run a larger real-generation gate after Phase 0 is committed and verified.

Required:

- Run 20-case OpenRouter-compatible benchmark gates when provider credentials are available.
- Include the default AI generation preset, currently `ocad_motion_v0`.
- Include `topdown_rpg_v0` when validating topdown-specific prompt/template/repair work or document why it was deferred.
- Record pass rate, usable rate, blocking errors, warnings, failure taxonomy, model/provider preset, image size, prompt contract version, and representative artifact paths.
- Update or add a decision note that states whether the next quality investment should be prompt changes, post-processing correction, provider comparison, or local repair.

Current decision:

- `ocad_motion_v0` is the default AI generation entry because its 20-case gate reached 0.95 usable rate while `topdown_rpg_v0` reached 0.15.
- `topdown_rpg_v0` remains the runtime profile, upload/manual-cut-line path, and repair fallback.
- The OCAD report layer separates expected fixed-region source reuse from unexpected duplicate motion, and source-region edge pressure is now diagnostic unless runtime edge/crop risk appears.

If live provider credentials are unavailable, run provider-free checks and leave the live gate as a documented blocker without marking Phase 1 complete.
