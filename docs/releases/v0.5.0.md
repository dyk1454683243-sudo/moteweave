## Scope

v0.5.0 consolidates the maintained local product surfaces delivered after
v0.4.0. Studio is now the sole maintained browser application, Editor
Workspace v0 remains available through its dedicated entry, and the existing
artifact-first Character, Motion, Scene, Project, benchmark, and engine-export
contracts remain in place.

Release preparation changed metadata and documentation plus one test-only
process-startup window. Product implementation and API protocols are unchanged.
It made no Provider call and generated no product artifact.

## Highlights

- Studio rail: Character, Action, Sequence, Tiles, Scene, Project, QA, and
  Settings use accepted Figma Current states and capability-bound controllers.
- Character: standard and advanced local processing, strict reviewed
  generation, direct compatibility generation, current-input release binding,
  deterministic Character prompt assistance, and session-only advanced
  Provider configuration.
- Action and Editor: guarded Motion Source lifecycle and reviewed set apply;
  Editor Workspace v0 project persistence, scene authoring, timeline,
  interaction/playtest, scene flow, export review, and consumer evidence.
- Scene: provider-free ingest remains available alongside explicitly
  quota-confirmed live generation. The live evidence remains a one-case smoke.
- Project: combines and validates existing Character and Scene artifacts; it
  has no independent generation path and stays gated by its manifest,
  validation, exact Job URLs, and current bindings.
- Legacy retirement: the old root HTML/CSS/controller shell is removed after
  every maintained capability reached Studio. Backend, CLI, Editor, benchmark,
  shared pure logic, and `src/v8.css` remain maintained.

## URL Compatibility

`/` and `/index.html` redirect to Character Studio. `/legacy`, `/legacy/`, and
`/legacy.html` accept only the following fixed mappings:

| Legacy tab | Studio destination |
|---|---|
| `character-pack` | `#character` |
| `motion-source` | `#action` |
| `sprite` | `#sequence` |
| `two-point-five-d` | `#tiles` |
| `prompts` | `?open=scene-prompt#scene` |
| `project-pack` | `#project` |
| `qa` | `#qa` |

Missing, empty, unknown, repeated, illegal, and prototype-key tab values use
the fixed Character destination. User query values are never concatenated into
redirect targets.

## Claim Boundaries

- The recorded live Scene gate remains a one-case release smoke. It does not
  establish broad Scene generation or WFC production readiness.
- Fixed-region Character calibration has one recorded single-call `1K`
  acceptance. It is not a sampled Provider-quality claim.
- `quality_character_v0` is a single-image, export-only result and is not a
  Project candidate. Only a complete, verified `production_sheet_v0` result
  can become a Project Character candidate.
- `review_required` and `diagnostic_only` compatibility results do not unlock
  Accept, export, or a Project candidate.
- Semantic blocking and adaptive Provider candidate spending remain outside
  this release claim.
- Hosted persistence, authentication, billing, and public deployment hardening
  are not included.

## Attribution And Repository Hygiene

- Direct dependencies remain `sharp` (Apache-2.0), `jszip` (MIT), and `gifenc`
  (MIT); all are covered by `ATTRIBUTIONS.md`.
- Existing public-format, Editor clean-room research, and OKLab math
  attribution entries remain current.
- This release adds no dependency, public format, bundled asset,
  model, binary, or training data.
- `.env`, `generated/`, `output/`, `node_modules/`, `.npm-cache/`, and local
  scratch files remain release-excluded and must not be staged.

## Publication Boundary

Publishing v0.5.0 creates a Git tag and GitHub Release for this local source.
It does not deploy a hosted service, publish an npm package, call a Provider,
or upload local generated artifacts. Post-release defects are fixed on `main`
and released under a new version such as `0.5.1`; the `v0.5.0` tag is not
rewritten.
